# 利润预测 Skill 与演示方案

新增入口 `/growth`，首页导航“利润预测与目标”。本轮只更新 GitHub 源码，未更新原 Netlify 网站。

## 演示顺序

1. 查看公开原始销售的日趋势和末7天对比；2022年9月24—30日净额20,926.2457元，前7天23,470.5955元，变化-10.8406%。展示历史数据真实涨跌，不预设必须增长。
2. 从商品贡献和回落排名选择重点商品，在经营问答里回查销售及毛利依据。历史变化是分析线索，不能直接归因为缺货或活动。
3. 设置未来30天目标净利润10000元（拟），查看零变化基准5536.1401元（拟）。基线与原经营台账、Excel一致。
4. 调整销量和损耗条件，查看收入、成本、损耗、其他费用、净利润及贡献拆解。压力/当前设想/顺利情景展示对假设的敏感性，不表示概率。
5. 保存演示方案，并把当前条件带进智能体对话，执行“理解—工具计算—核查”流程。保存只在此设备，不写入流水。

## 数据边界

真实可追溯的内容：原表商品、销量、售价、销售/退货类型，以及参考批发价和近期损耗率。销售净额是数量乘单价演算，原表没有实收小票金额。

演示内容（拟）：日期平移、供货关系、采购、库存、费用、收付款、利润与未来目标。新增功能没有伪造真实经营凭证，也没有修改历史交易。没有成本与费用原始凭证，无法把拟定利润变成真实财务事实。

## 计算

共享入口 `lib/profit-forecast.ts`。网页读取由原账套生成的轻量基线；服务器问答和技能脚本直接使用同一账套。

周期基准按日均折算。销量变化同时影响收入、销售成本和损耗；售价变化作用于收入；单位成本变化同时作用于销售成本和损耗费用；损耗改善是费用相对减少；其他费用按周期折算后再调整。

所有计算保留整数万分之一元，明细最多展示四位小数；概览展示两位。贡献拆解合计严格等于净利润变化。

其他经营条件保持不变时，用贡献毛利代数求解目标所需销量。无法据此保证市场需求、供货、人力或资金满足。未建立价格弹性、促销因果和节假日模型，因此功能定位为可解释的条件预测。

## 技能使用

技能说明 `skills/profit-forecast/SKILL.md`；执行器 `skills/profit-forecast/scripts/forecast.mjs`。默认30天、变化0、演示目标10000元。传入JSON条件可复算用户方案。脚本只输出结果，不改历史账套。

公开问答新增“利润预测与目标测算”工具，离线规则模式也可执行。指定月份暂不映射为任意30天，要求使用未来明确天数；当前技能分析全店净利润，单品仍通过商品工具查询销量及毛利。

## 验证范围

自动验证覆盖：每日及商品汇总与账套一致、原始日期保留、零变化基准、联合条件贡献平衡、损耗与售价改善贡献、周期切换、无效输入和非正贡献情形，以及智能体正确选择利润工具且不生成备货记录。

本地浏览器检查：1440×900、768×1024、390×844、320×568；无页面横向溢出。检查了滑块重算、演示方案保存、条件带入问答及实际利润工具执行。浏览器尺寸模拟不等于真实手机验收。

该轮新工具的验证使用本地规则模式和回归测试，不宣称已完成新功能的线上豆包模型评测。
