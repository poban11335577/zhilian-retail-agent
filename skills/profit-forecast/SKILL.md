# 利润预测与目标测算

在项目根目录运行。基线使用公共案例的同一账套；需求使用 `lib/stock-forecast.ts`，目标方案使用 `lib/goal-planner.ts`，历史费用情景使用 `lib/profit-forecast.ts`。网页入口 `/growth`，问答与脚本共享计算。

## 执行

运行 `node skills/profit-forecast/scripts/forecast.mjs` 获得零变化基准情景。用户指定条件时，将 JSON 文件路径作为唯一参数传入：

```text
node skills/profit-forecast/scripts/forecast.mjs conditions.json
```

输入允许 `days`（1—60整数）、`quantityChange`（销量变化%，-50—100）、`priceChange`（售价变化%，-20—20）、`costChange`（单位成本变化%，-20—50）、`lossReduction`（损耗相对改善%，0—100）、`fixedChange`（其他费用变化%，-50—100）、`target_scaled`（目标，元×10000整数）、`budget_scaled`（全周期采购预算，元×10000非负整数；null表示未设累计上限）。默认变化0、30天、演示目标10000元（拟）。不要自行填入“行业平均提升率”。

先阅读 `planning`：推荐、三种经营方案、逐商品分日清单、预算限制、可支持销量、净利润、目标缺口及对账。自动方案只搜索当前销量变化上额外增加0至30个百分点，降损至少20%（拟）；这些是待验证条件，不是已实现增长。脚本输出到标准输出，不写回账套。

`result` 与 `scenarios` 保留历史月度费用整体变动情景，未检查供货；不得把它们当作联动方案已可实现的结果。两类计算的损耗口径不同，必须明确说明。

## 解释结果

- 先给出推荐方案、净利润和目标差距，再解释经营条件、预算能支持的销量及分日采购。查询数值来自输出，不由模型重新估算。
- 历史销售数量及单价有公开原始来源，销售额是数量×单价的演算值。日期平移、采购成本、损耗费用和其他费用仍为（拟）；不得将它们描述为原门店真实利润。
- 需求变化是用户假设，模型未识别价格弹性、促销因果、季节或节假日效应。三个情景不是统计置信区间，不代表发生概率。
- 联动方案的降损相对降低商品参考损耗率，重算采购及报损；旧费用情景相对降低损耗费用，两者不混用。未来可售按0，分日到货，未售生鲜按当天清理（拟）。采购支出已分解到净售和报损成本，不重复扣除。
- 缺少真实成本、费用或实收凭证时，只能输出条件测算；无法凭空补出真实财务事实。发生非零对账差异时脚本停止。
- 利润不等于现金。该技能不触发采购、付款、入库或变更历史账套；保存演示方案也不表示目标已实现。
- 连续对话以服务端保存的 `profitContext` 为准，只有明确修改的条件才覆盖；选择上一轮方案后再应用新条件。CLI每次为独立输入，不从任意聊天文字猜测旧条件。
- 预算为全周期累计采购上限，先按比例覆盖日期与商品，再按贡献分配剩余包装。分配不证明全局最优；库存效期、供应商交期和真实资金仍需核实。全部方案都未达到目标时报告缺口。
- 需要达到目标的销量变化是保持其他假设不变的代数解。超过技能范围、贡献毛利不为正或经营条件不支持时，说明条件不足，不承诺能实现。
