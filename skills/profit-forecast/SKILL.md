# 利润预测与目标测算

在项目根目录运行。数据基线使用 `lib/case-book.ts` 的同一账套，计算使用 `lib/profit-forecast.ts`，网页入口为 `/growth`。网页、问答工具和脚本共享公式。

## 执行

运行 `node skills/profit-forecast/scripts/forecast.mjs` 获得零变化基准情景。用户指定条件时，将 JSON 文件路径作为唯一参数传入：

```text
node skills/profit-forecast/scripts/forecast.mjs conditions.json
```

输入允许 `days`（1—60整数）、`quantityChange`（销量变化%，-50—100）、`priceChange`（售价变化%，-20—20）、`costChange`（单位成本变化%，-20—50）、`lossReduction`（损耗费用相对降低%，0—100）、`fixedChange`（其他费用变化%，-50—100）、`target_scaled`（利润目标，人民币元×10000整数）。未指定的变化为0，默认30天；默认目标10000元是演示目标（拟）。不要自行填入“行业平均提升率”。

输出含基线来源、原始日期、演示日期、输入条件、逐项利润变化、目标差距以及压力/当前/顺利情景。脚本输出到标准输出，不写回账套。

## 解释结果

- 先说明周期与输入条件，再说明收入、销售成本、损耗、其他费用及净利润；展示影响最大的一项和距目标还差多少。
- 历史销售数量及单价有公开原始来源，销售额是数量×单价的演算值。日期平移、采购成本、损耗费用和其他费用仍为（拟）；不得将它们描述为原门店真实利润。
- 需求变化是用户假设，模型未识别价格弹性、促销因果、季节或节假日效应。三个情景不是统计置信区间，不代表发生概率。
- 损耗改善指损耗费用相对减少，而非损耗率直接减少若干百分点。销量增加也会增加销售成本和损耗费用。
- 缺少真实成本、费用或实收凭证时，只能输出条件测算；无法凭空补出真实财务事实。发生非零对账差异时脚本停止。
- 利润不等于现金。该技能不触发采购、付款、入库或变更历史账套；保存演示方案也不表示目标已实现。
- 需要达到目标的销量变化是保持其他假设不变的代数解。超过技能范围、贡献毛利不为正或经营条件不支持时，说明条件不足，不承诺能实现。
